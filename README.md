# GitVerse AI Engineering Lab — творческий итоговый проект

**Форкните репозиторий, разработайте свой полезный проект и покажите его работу через GitVerse CI/CD.**

Здесь нет единого правильного приложения. Можно использовать Python, JavaScript, другие языки, ML, NLP, LLM, MCP, Agent Harness — или обойтись без нейросетей, если идея хороша.

## Начать за 5 минут

1. Создайте **fork** этого репозитория в GitVerse. Проверьте, что это не зеркало.
2. Откройте **Настройки → Репозиторий** и убедитесь, что CI/CD включён.
3. Запустите вручную **`01 - Quality CI`**. **Первый запуск должен завершиться с ошибками**: это специально.
4. Прочитайте ошибки `lint` и `tests` в журнале, исправьте исходник `src/starter.py`, сохраните коммит и добейтесь успешного Quality CI.
5. Выберите собственную идею и переделайте **`02 - Project CI`**, который пока лишь демонстрирует работу с артефактами. Разрешается полностью заменить Python-пример.
6. Заполните **[AI_MODELS.md](AI_MODELS.md)** — обязательно укажите все использованные модели при разработке и/или работе приложения, либо прямо заявите, что ИИ не применялся.
7. Заполните [SUBMISSION.md](SUBMISSION.md): приложите ссылки на запуски и объясните, что именно было сделано.

Полная постановка задания: **[TASK.md](TASK.md)**. Критерии оценивания: **[docs/RUBRIC.md](docs/RUBRIC.md)**.

## Два CI/CD-процесса

| Workflow | Когда запускается | Что демонстрирует |
|---|---|---|
| `01-quality.yaml` | Push в `master` и вручную | Умение находить и исправлять замечания к качеству кода |
| `02-project.yaml` | Вручную | Настоящее полезное действие и сохранение результата |

**Важно:** зелёная галочка на неизменённом демонстрационном Project CI **не даёт баллов за творческий проект**. Нужно создать собственную полезную автоматизацию. Quality CI также проверяет, что декларация `AI_MODELS.md` заполнена — но не может установить правдивость заявленного использования моделей.

## Что уже есть в шаблоне

```text
.gitverse/workflows/
    01-quality.yaml       # проверка качества, содержит настоящие замечания
    02-project.yaml       # пример производящего и потребляющего jobs
src/
    starter.py            # специально оставленные ошибки
    project_demo.py       # временный пример обработки CSV
scripts/
    quality_gate.py       # последовательный запуск нескольких проверок
    repo_hygiene.py       # обнаруживает нежелательные файлы в Git
    check_ai_declaration.py # проверяет факт декларации ИИ
    verify_result.py      # пример чтения артефакта в отдельном job
tests/
    test_starter.py       # демонстрирует ошибки в starter.py
    test_project_demo.py  # проверяет демонстрационный сценарий
data/sample.csv
TASK.md                   # условия задания
AI_MODELS.md              # обязательная декларация моделей ИИ
SUBMISSION.md             # короткая форма сдачи
```

## Запуск примера локально

```bash
python -m pip install -r requirements-dev.txt
python scripts/quality_gate.py
python -m src.project_demo --input data/sample.csv --output dist
python scripts/verify_result.py dist/
```

Пример не требует ключей API и работает офлайн. На GitVerse для демонстрации передачи файлов между job используется `actions/upload-artifact@v4` и `actions/download-artifact@v4`.

## Примеры направлений

- Agent Harness с управлением контекстом, ограничениями и состоянием.
- MCP-инструменты или агент, выполняющий полезную цепочку действий.
- NLP/ML-пайплайн с обработкой входных данных и созданием отчёта.
- Анализатор репозитория, генератор документации, выпуск release notes.
- Публикация небольшого сайта или интерактивного результата.
- **Своя идея** — допускается, если есть содержательная автоматизация.

Подробные варианты: [docs/IDEAS.md](docs/IDEAS.md).

## Ограничения и безопасность

- Использование ИИ разрешено, но **обязательно декларируйте конкретные модели** в `AI_MODELS.md` (включая помощь при разработке). Если не пользовались ИИ, укажите это явно.
- Не помещайте токены, пароли и API-ключи в код, README и артефакты. Пользуйтесь секретами GitVerse.
- Не позволяйте агенту выполнять произвольные команды с доступом к секретам и токенам CI.
- Демо должно быть безопасным, ограниченным по времени и стоимости; желательно иметь режим без внешнего API.
- Не маскируйте ошибки через `|| true`, `continue-on-error` и необоснованные исключения из проверок.
- Не загружайте приватные персональные данные и большие датасеты без разрешения.

Вопросы по триггерам, раннерам и артефактам сверяйте с [документацией GitVerse CI/CD](https://gitverse.ru/docs/cicd/).
