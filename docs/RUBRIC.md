# Критерии оценивания — 15 баллов

Преподаватель оценивает содержательность проекта и свидетельства работы в репозитории. Зелёный CI сам по себе не означает полный балл.

| Критерий | Баллы | На что смотрит преподаватель |
|---|---:|---|
| Quality CI: обнаружение и исправление замечаний | **3** | Есть реальные неудачные запуски, изменения кода, успешное повторное выполнение; проверки не отключены |
| Quality CI: качество проверок собственного проекта | **2** | Проверяется важное для проекта поведение или качество, а не только наличие файлов |
| Project CI: полезная автоматизация | **4** | Workflow запускает существенный функционал, а не имитирует деятельность |
| Project CI: осмысленная организация CI/CD | **2** | Шаги/jobs/условия/внешние зависимости связаны с задачей и корректно работают |
| Наблюдаемый результат | **2** | Есть новый артефакт/публикация/отчёт/выходные данные, подтверждающие работу |
| Идея, README, декларация моделей ИИ и самостоятельный вклад | **2** | Понятная задача, качественная документация, согласованная с проектом декларация `AI_MODELS.md`, объяснены решения и новизна |
| **Всего** | **15** | |

Преподаватель вправе поставить частичный балл в каждом критерии; значения не обязательно целые.

**Декларация обязательна независимо от факта использования ИИ.** Её отсутствие или
формальное заполнение — недостаток оформления, учитываемый в последнем критерии.
Само использование ИИ не является причиной для снижения балла. Если обнаружено
несоответствие между заявленными и фактически используемыми моделями,
преподаватель уточняет обстоятельства и оценивает достоверность самостоятельного вклада.

## Примеры формализма, который НЕ засчитывается

- CI запускает `echo "All good"` и всегда возвращает успех.
- Линтер сообщает ошибки, но студент ничего не исправляет.
- Проверки отключены или опасные предупреждения игнорируются ради зелёной галочки.
- Тесты проверяют константу, не связанную с программой.
- Project CI только повторяет неизменённый учебный пример.
- Workflow успешно завершился, но нет полезного результата или его невозможно найти.
- Проект объявлен «агентом», но в действительности лишь отправляет один запрос к LLM без заявленной логики.
- `AI_MODELS.md` не заполнен, вместо конкретных моделей перечислены только сервисы или указанные модели противоречат конфигурации проекта.

## Порядок проверки

1. Открыть `SUBMISSION.md`, README и `AI_MODELS.md`; проверить наличие декларации и согласованность названий моделей.
2. Проверить несколько запусков `01 - Quality CI`: было ли замечание и реальная реакция.
3. Открыть настройки `02 - Project CI`, последний успешный запуск и его результат.
4. Проверить, чем работа отличается от исходного шаблона или прежней собственной работы студента.
5. Заполнить критерии в Moodle.
