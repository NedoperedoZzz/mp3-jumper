# Критерии оценивания — 15 баллов

Оценка выставляется преподавателем по checklist в Moodle. Оба workflow студент **пишет сам**. Не требуется специально создавать неудачные запуски; при возникновении замечаний важно на них реагировать.

| Критерий | Баллы | Что смотрит преподаватель |
|---|---:|---|
| **Quality CI: содержательные проверки** | **2** | Не менее двух уместных проверок, одна из них затрагивает реальное поведение или важное свойство собственного проекта |
| **Quality CI: понятная обратная связь** | **2** | В CI видно, что и как проверялось, какие результаты и реальные диагностические сообщения получены; ошибки честно влияют на статус |
| **Quality CI: работа с замечаниями** | **2** | Проверяется актуальный код; замечания разобраны и исправлены либо обоснованы; финальный запуск успешен. Если замечаний не было, искусственные ошибки не нужны |
| **Project CI: полезная автоматизация** | **4** | Отдельный самостоятельно созданный workflow выполняет существенный сценарий проекта, а не формальную команду |
| **Project CI: наблюдаемый результат** | **3** | Преподаватель может открыть результат, понять связь с входными данными и убедиться, что он создан CI |
| **Идея, README, самостоятельный вклад, декларация моделей** | **2** | Понятна задача и новизна; есть навигация по проекту и полная честная декларация `AI_MODELS.md` |
| **Итого** | **15** | |

Допускаются промежуточные баллы. Наличие двух зелёных workflow само по себе не гарантирует высокий балл, как и использование сложной модели не даёт автоматического бонуса.

**Обязательная декларация ИИ**: в `AI_MODELS.md` перечислены конкретные модели, использованные при разработке или работе проекта, либо указано отсутствие использования. Пропуски и противоречия учитываются в последнем критерии. Использование ИИ само по себе не штрафуется.

## Типичные причины снижения баллов

- Есть Quality CI, но он не проверяет новую программу или сводится к `echo PASS`.
- Логи не позволяют понять, что именно проверялось и как.
- Замечания проигнорированы, проверки выключены, ошибки скрыты, а workflow искусственно сделан зелёным.
- Есть только линтер или оформление файлов без проверки значимого свойства работы проекта.
- Project CI только устанавливает зависимости, запускает тесты Quality или печатает демонстрационное сообщение.
- Результат проекта есть только локально, но не создаётся и не демонстрируется в CI.
- Невозможно найти артефакт/публикацию по предоставленной ссылке.
- Повторно сдан старый проект без существенного нового вклада.
- Декларация ИИ отсутствует, названы лишь интерфейсы вместо моделей либо обнаружены несогласованные заявления.

## Порядок проверки за несколько минут

1. Открыть `SUBMISSION.md` и README; понять задачу и вклад.
2. Перейти к Quality CI, посмотреть, **что и как проверялось** на актуальном коде и как студент работал с замечаниями (при наличии).
3. Открыть Project CI и подтверждённый им новый результат.
4. Проверить `AI_MODELS.md`.
5. Заполнить checklist в Moodle. При сомнениях — посмотреть исходники и diff.
