# GitVerse или GitHub — обе площадки разрешены

Вы выбираете **одну основную площадку** и на ней разрабатываете проект, настраиваете оба workflow и показываете историю запусков. Не требуется дублировать работу на двух площадках.

| | GitVerse | GitHub |
|---|---|---|
| Где лежат workflow | `.gitverse/workflows/` | `.github/workflows/` |
| Где смотреть запуски | Вкладка CI/CD | Вкладка Actions |
| Ручной запуск | `workflow_dispatch` | `workflow_dispatch` |
| Автоматический запуск Quality | Например, `push` | Например, `push`, `pull_request` |
| Где смотреть результат | CI-артефакты, Pages, другие ссылки | Actions artifacts, Pages, Releases, другие ссылки |
| Оценивание | Одни и те же требования | Одни и те же требования |

**Источник шаблона и платформа сдачи могут различаться.** Если шаблон опубликован только в GitVerse, на GitVerse делайте fork, а для GitHub создайте новый репозиторий на основе файлов шаблона или импортируйте репозиторий. На GitHub нельзя сделать обычный fork напрямую из GitVerse; это не требуется. Если преподаватель опубликовал отдельный GitHub template, можно использовать его.

## GitVerse

1. Создайте fork исходного репозитория.
2. Включите CI/CD в настройках, если требуется.
3. Самостоятельно создайте два workflow в `.gitverse/workflows/`.
4. Убедитесь, что они действительно запускаются и видны преподавателю.

Документация: [быстрый старт](https://gitverse.ru/docs/cicd/quick-start/), [синтаксис](https://gitverse.ru/docs/cicd/docs/workflow/), [артефакты](https://gitverse.ru/docs/cicd/manuals/artifacts/).

## GitHub

1. Создайте свой репозиторий из шаблона или импортируйте его содержимое.
2. Самостоятельно создайте два workflow в `.github/workflows/`.
3. Запустите их через GitHub Actions и предоставьте ссылки на runs и результаты.

Документация: [Workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax), [Manually running a workflow](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow).

## Независимость и безопасность

- Репозиторий должен быть доступен преподавателю, а история проверок и результаты — открываться по ссылкам.
- Секреты задавайте в настройках платформы. Не сохраняйте их в исходниках, логах и артефактах.
- Проверяйте доступность своих actions и раннеров на выбранной площадке; совместимость синтаксиса не означает абсолютную идентичность окружений.
- Ограничения хранения артефактов и квоты различаются по платформам. По возможности приложите к сдаче долговечную ссылку на публичный результат или краткое доказательство в README.
